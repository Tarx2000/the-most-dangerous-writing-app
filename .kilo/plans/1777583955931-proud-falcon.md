# Implementation Plan: Codebase Modularization

## Goal
Implement changes **2, 6, and 8** from the architectural audit to improve modularity and AI-agent friendliness.

## Changes to Implement

### 1. Split `types/index.ts` into Domain-Specific Type Modules (Change 2)

**Rationale:** The current `types/index.ts` file (~184 lines) mixes domains (Person, Notes, Vlogs, AI, Vision, Alignment). Splitting prevents merge conflicts, speeds up type-checking, and provides a clear place for new feature types.

**Target Structure:**
- `src/types/person.ts`: `Person`, `RELATIONSHIP_OPTIONS`
- `src/types/note.ts`: `SavedNote`, `SortOption`
- `src/types/vlog.ts`: `SavedVlog`
- `src/types/ai.ts`: `AiJob`, `AiJobCategory`, `AiQueueState`, `AiLogEntry`
- `src/types/vision.ts`: `VisionBoard`
- `src/types/alignment.ts`: `AlignmentReflection`, `isAlignmentReflection()`
- `src/types/feed.ts`: `FeedItem`, `FeedItemType` (Extracted from `components/features/feed/FeedCard.tsx` to avoid domain coupling)
- `src/types/index.ts`: Barrel re-export of all modules.
- `src/types/navigation.types.ts`: Remains as is.

**Action Items:**
1. Create the 7 new domain type files.
2. Migrate all type definitions and constants out of the old `index.ts`.
3. Ensure `isAlignmentReflection` is moved to `alignment.ts`.
4. Ensure `FeedItem` and `FeedItemType` are moved from `FeedCard.tsx` to `feed.ts`.
5. Update the root `index.ts` to re-export everything.

**Dependencies:**
- Identify all imports of `SavedNote`, `Person`, etc., from `@/types` in the codebase (use grep/rg).
- Verify no new circular dependencies are introduced. `FeedItem` depends on `SavedNote` and `SavedVlog`, which is fine as long as it only imports types, not the barrel index.

### 2. Create Barrel Exports (`index.ts`) for Key Directories (Change 6)

**Rationale:** AI agents and developers should be able to import from a domain directory (`@/types`, `@/config`, `@/components/ui`) without memorizing exact filenames, reducing the cognitive load and preventing import churn during refactors.

**Target Directories:**
1. **`src/types/`:** Already handled by the split above (new `index.ts`).
2. **`src/config/`:** Create `src/config/index.ts`. Currently, `index.ts` contains `APP_VERSION`, `VERSION_HISTORY`, and `CONFIG`. After Change 8, this file will only re-export from `config.ts` (or rename `index.ts` to `config.ts`).
3. **`src/components/ui/`:** Create `src/components/ui/index.ts`. It will export all 14 primitives:
   - `ActionSheet`, `AnimatedScaleButton`, `AnimatedSymmetricalRing`, `CarouselSelector`, `ConfirmDialog`, `ErrorBoundary`, `LiquidGlassNav`, `LiquidMorphIcon`, `PinPadModal`, `RichText`, `SettingsCard`, `ShimmerLine`, `SwipeableModal`, `TickDial`.

**Action Items:**
1. Create `src/components/ui/index.ts`.
2. Update `src/config/index.ts` (see Change 8).
3. Update `tsconfig.json` or `package.json` if needed (not expected, Metro handles barrel files). Ensure `tsconfig` path mapping `@/components/ui` resolves to the directory, and files importing `@/components/ui/SwipeableModal` still work.

**Dependencies:**
- List all 14 files in `components/ui/` to ensure the barrel export is complete.
- Ensure default exports don't conflict (if any). All UI primitives appear to be named exports.

### 3. Remove `VERSION_HISTORY` from `config/index.ts` (Change 8)

**Rationale:** `VERSION_HISTORY` is a static changelog object (15 lines), not a runtime configuration constant. It is only imported by `StartScreen.tsx`. Moving it to a dedicated file cleans up the config domain.

**Target Structure:**
- `src/config/changelog.ts`: `VERSION_HISTORY` array.
- `src/config/index.ts`: `APP_VERSION`, `CONFIG` constants. Becomes a thinner barrel.

**Action Items:**
1. Create `src/config/changelog.ts`.
2. Remove `VERSION_HISTORY` from `src/config/index.ts`.
3. Update `src/screens/StartScreen.tsx` to import `VERSION_HISTORY` from `@/config/changelog`.

**Dependencies:**
- Grep `VERSION_HISTORY` usage to confirm it's only in `StartScreen.tsx` and `config/index.ts`.

## Risks & Mitigations
- **Broken Imports:** `grep` was already run. We have a list of ~54 files importing from `@/types` and ~30 from `@/config`. The barrel exports ensure they still resolve.
- **Metro/TypeScript Resolution:** Metro must resolve `@/components/ui` to its `index.ts`. Since `@/types` and `@/config` already work this way (via their `index.ts`), the same pattern is safe.
- **`FeedItem` Move:** Ensure `FeedCard.tsx` is updated to import `FeedItem` from `@/types` instead of defining it locally. This is a critical change to ensure the type split is effective.
