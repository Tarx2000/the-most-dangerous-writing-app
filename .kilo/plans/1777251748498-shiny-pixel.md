## Steps

### 1. Create `.kilo/kilo.json` — Register External Skill Directory
Create `kilo.json` at the project root (inside `.kilo/` is also valid, but root is conventional) with:
```json
{
  "skills": {
    "paths": [".agents/skills"]
  }
}
```
This causes Kilo to discover all existing `.agents/skills/<name>/SKILL.md` files **without moving or duplicating** them. Both Claude (via `.agents/`) and Kilo (via this path) can then use the same source of truth.

### 2. Create `.kilo/workflows/` — Migrate Workflows to Kilo Commands
Copy each `.md` file from `.agents/workflows/` into `.kilo/workflows/`.
- The existing files already have YAML frontmatter (`description: ...`), which is the exact format Kilo expects for workflow-to-command conversion.
- On next startup, Kilo will auto-register them as slash commands (e.g., `/expo-build`, `/react-native-performance`, `/ux-polish`, etc.).

### 3. Create Root `AGENTS.md` — Central Project Context for All Agents

## Decision Points / Clarifications for User
1. **Should workflows also be duplicated, or should we reference `.agents/workflows/` somehow?**
   Kilo only auto-converts workflows from `.kilo/workflows/` (or global equivalents). There is no config to point it at `.agents/workflows/`. Therefore a copy into `.kilo/workflows/` is required for native slash-command support.
2. **Should root `AGENTS.md` replace `CLAUDE.md`, or coexist?**
   Coexistence is recommended — Kilo reads both automatically, and Claude Code explicitly expects `CLAUDE.md`. `AGENTS.md` will serve as the unified agent-facing document while `CLAUDE.md` stays for the existing Claude/Codex bridge.
3. **Should I also create `.kilo/command/*.md` wrappers?**
   Not necessary unless the user wants custom `/command` logic beyond what the workflow frontmatter provides. The plan sticks to Kilo's native workflow-to-command conversion.
