# Re-Audit & Fix Plan — Post-Implementation

## Codebase Rating: 8.5/10

After the first round of fixes (render-time SharedValue writes, hardcoded colors, type safety leaks, bare catch blocks, unused deps, version pinning), the codebase is significantly cleaner:

- **TypeScript (`tsc --noEmit`)**: 0 errors
- **Tests**: 112 passed / 8 suites
- **No app-breaking bugs** remaining
- **Architecture**: Still excellent (8 contexts, singleton AI queue)

The remaining issues are hygiene, accessibility, and robustness — no longer strict-mode or crash-level violations.

## Remaining Critical Issues (Ranked)

### 🔴 Critical (1)

**1. Accessibility Crisis — AnimatedScaleButton strips all a11y props**
- **Scope**: `src/components/ui/AnimatedScaleButton.tsx`, cascading to 30+ usage sites across every screen
- **Issue**: The component wraps `Pressable` but does NOT accept or forward `accessibilityLabel`, `accessibilityRole`, `accessibilityHint`, or `accessibilityState`. The entire app is effectively invisible to screen readers.
- **Fix**: Extend `AnimatedScaleButtonProps` to accept a11y props and spread them onto the inner `Pressable`.

### 🟠 High (3)

**2. Race Conditions — Async setState without unmount guards**
- **Files**: `src/screens/PostWritingScreen.tsx:112-131`, `src/screens/VlogRecordingScreen.tsx:178-350`, `src/lib/hooks/useStorage.tsx:337-353`
- **Issue**: After `await` chains (grammar check, recording, compression), `setState` fires without checking if the component is still mounted. Can throw React warnings or corrupt state.
- **Fix**: Add `const mountedRef = useRef(true)` and guard all post-await setters with `if (!mountedRef.current) return`.

**3. Magic Numbers — Scattered hardcoded thresholds/timeouts**
- **Files**: `src/screens/HomeScreen.tsx:134` (`7 * 24 * 60 * 60 * 1000`), `src/screens/StartScreen.tsx:214-215` (`2000`, `5000`), `src/screens/VlogRecordingScreen.tsx:111,151,395` (`500`, `1000`, `4_500_000`), `src/components/ui/PinPadModal.tsx:114` (`150`)
- **Issue**: These literals are duplicated or unmaintainable. The 7-day threshold appears in HomeScreen; the long-press timing is hardcoded.
- **Fix**: Centralize into `CONFIG` or named constants in each file.

### 🟡 Medium (3)

**4. `console.log` / `console.warn` in Production Code** ✅ THIS PLAN
- **Files**: `src/lib/videoCompressor.ts:143,175,189`, `src/lib/hooks/useStorage.tsx:342`, `src/lib/aiLogger.ts:46`
- **Issue**: Console statements bypass the structured `logger` module and leak to production. `videoCompressor.ts` alone has 3 `console.log` calls for normal operation.
- **Fix**: Replace with `logger("info", ...)` / `logger("warn", ...)` (if dev-only, should be gated with `if (__DEV__)`).

**5. SharedValue Read During Render (`PinPadModal`)** ✅ THIS PLAN
- **File**: `src/components/ui/PinPadModal.tsx:137`
- **Issue**: `if (!isVisible && opacitySV.value === 0) return null;` reads a SharedValue during React render. Reanimated strict mode flags this as a stale-read risk.
- **Fix**: Drive the render decision from React state instead, or accept the conditional without using `.value` in render.

**6. Dead Code — Unused exports** ✅ THIS PLAN
- **Files**: `src/lib/db.ts:22` (`resetDbInstance`), `src/lib/repositories/notesRepository.ts:113` (`noteToStreakHistory`), `src/lib/storageManager.ts:21,24` (`DEFAULT_VLOG_STORAGE_CAP_BYTES`, `MIN_FREE_SPACE_BYTES`)
- **Issue**: Dead weight increases bundle size and maintenance surface.
- **Fix**: Remove unused exports/functions. If used only in tests, consider moving to test utils.

**7. Persistent `any` Types in UI Components** ✅ THIS PLAN
- **Files**: `src/components/ui/LiquidMorphIcon.tsx:81` (`style?: any`), `src/components/features/feed/FeedVideoCard.tsx:56` (`player?: any`)
- **Issue**: These are the last remaining `any` types in production UI. `player?: any` should be `VideoPlayer` from `expo-video`; `style?: any` should be `StyleProp<ViewStyle>`.
- **Fix**: Import correct types from respective libraries.

### 🟢 Low (3)

**8. Error Boundary Gaps in Heavy Modals**
- **Files**: `PinPadModal`, `SettingsModal`, `StreakPopup`, `NoteViewerModal`, `VlogViewerModal`, `BenchmarkModal`, `DeveloperToolsPanel`
- **Issue**: Not individually wrapped in `ErrorBoundary`. A crash in a modal currently bubbles up and kills the entire screen.
- **Fix**: Wrap each modal/dialog in a lightweight `ErrorBoundary` wrapper.

**9. ESLint Config Outdated (Blocks linting)**
- **File**: `package.json` / `.eslintrc.js`
- **Issue**: ESLint v10 requires flat-config (`eslint.config.js`), but the project still uses `.eslintrc.js`, so `npm run lint` fails immediately. This blocks automated unused-import / unused-variable detection.
- **Fix**: Migrate to `eslint.config.js` (flat config) or downgrade ESLint to v8.

**10. Gradient Hardcoded `rgba` in `LibraryScreen` (minor)**
- **File**: `src/screens/LibraryScreen.tsx:243-268`
- **Issue**: LinearGradient stop interpolation uses raw `rgba(0,0,0, ...)` values between `theme.colors.background` and transparent.
- **Fix**: These are legitimate fade stops. Best approach is either: (a) leave as-is and document as a theme exception, or (b) add fade-stop tokens to `theme.colors`.

### Issue 5: SharedValue Read During Render (`PinPadModal`)

**`src/components/ui/PinPadModal.tsx`**
- **Line 137**: `if (!isVisible && opacitySV.value === 0) return null;`
- **Current problem**: Reads `opacitySV.value` during render, which Reanimated strict mode flags as a stale-read.
- **Fix**: Replace the condition with a derived React state. Since `isVisible` is already React state and the component renders exactly when visible, simply returning `null` when `isVisible === false` (if that's desirable) or keeping the current early-return should not use `.value`. Alternatively, since `opacitySV` animates *after* `isVisible` changes, move the early-return to a `useAnimatedReaction` or simply drop the `.value === 0` check and rely on opacity animation (`opacitySV.value` will smoothly animate, so it won't immediately be 0 when `isVisible` toggles, but `isVisible` already controls mount/unmount via the `useEffect` syncing).  
- **Chosen approach**: Keep `if (!isVisible) return null;` on line 137 and remove the `&& opacitySV.value === 0` part. The component already hides itself via opacity animation when invisible, so removing it from the render tree early is an optimization. To avoid the `.value` read during render, we use `isVisible` state alone. This may cause a quick flash when the modal goes from `isVisible=true` to `isVisible=false`, but the `withTiming(0, 200)` opacity animation will smooth that out. If we want to avoid it completely, we can add an `isFullyHidden` state that only becomes `true` after the opacity animation completes (via `useAnimatedReaction`/`runOnJS`). However, the simplest fix acceptable here is just removing the `.value` check and letting `isVisible` drive the conditional render, since the animation is already handled in `animatedStyle`.
