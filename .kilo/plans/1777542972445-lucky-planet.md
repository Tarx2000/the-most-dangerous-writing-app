# AI Processing Stability & Bug-Fix Plan

## Executive Summary
After auditing the entire AI pipeline (`aiService.ts`, `aiQueue.ts`, `aiLogger.ts`, `useAiQueueProvider.tsx`, `config/ai.ts`, `types/index.ts`, and all consumer screens), I found **16 distinct bugs and architectural issues**. The three most critical ones can cause infinite retry loops, silently skipped AI jobs, and queue state loss on unmount.

---

## 🔴 CRITICAL (App-breaking / Infinite loops / Data loss)

### 1. Missing/Invalid API Key → Rapid-fire retry storm (User-reported bug)
**Files:** `src/lib/aiQueue.ts:456-576`, `src/lib/aiService.ts:484-521`
**Root cause:** `pingServer()` treats HTTP 401 as "server online" (`response.status === 401` is in the `isOk` check). The queue then attempts every job, `processNote()` catches the 401 internally and returns `failed: true`, the queue throws and retries up to 2 more times per note, then marks `failed`. With 500 ms delays, a 50-note batch rapidly burns 150 requests with **zero user-facing error**.
**Fix:**
- Remove 401/403 from `pingServer()` "online" check.
- Add `!config.apiKey` or `config.apiKey.length < 10` early-guard in `processNext()` — fail the job immediately with `error: 'No API key configured'` and do NOT retry.
- Surface `lastError` containing auth hints in the UI (`StartScreen` batch panel, `PostWritingScreen` shimmer).

### 2. `AiQueueProvider` unmount destroys the singleton queue
**File:** `src/lib/hooks/useAiQueueProvider.tsx:81-86`
**Root cause:** `useEffect(() => { return () => { aiQueue.shutdown(); }; }, []);` runs on every component unmount (React Strict Mode double-mount in dev, Fast Refresh, navigation). `shutdown()` wipes `this.jobs = []` and sets `initialized = false`. Any queued or in-flight jobs are lost.
**Fix:** Remove the unmount cleanup entirely. The singleton queue must survive component lifecycles. Only call `shutdown()` in explicit app-termination scenarios (not implemented — acceptable).

### 3. Queue never initializes if `savedNotes.length === 0` at mount
**File:** `src/lib/hooks/useAiQueueProvider.tsx:106-111`
**Root cause:** Auto-init runs only when `savedNotes.length > 0`. If the user writes their very first note and `enqueueNote()` is called, `startProcessing()` returns early because `!this.initialized` (line 425). The AI job is silently dropped.
**Fix:** Remove the `savedNotes.length > 0` guard. Initialize the queue immediately when the provider mounts (or on first `enqueueNote()`).

## 🟠 HIGH (Incorrect behavior / Race conditions / Code quality)

### 4. Deleted notes marked as `done` instead of `failed`
**File:** `src/lib/aiQueue.ts:478-484`
**Issue:** When a note is deleted while its job is queued, the job is marked `status = 'done'` — implying success.
**Fix:** Change to `status = 'failed'` with `error = 'Note deleted'`.

### 5. `cancelJob()` race condition allows saving after cancel
**File:** `src/lib/aiQueue.ts:200-217`, `499-507`
**Issue:** `cancelJob()` aborts the XHR and sets `job.status = 'failed'`, but `processNext()` may still be executing past the `await processNote()` line. If the abort races with resolution, results can be saved.
**Fix:** After `processNote()` resolves, check `job.status !== 'processing'` before calling `updateNote()`. If cancelled, discard results.

### 6. Deprecated `useAiQueue` hook still exists and can be imported
**File:** `src/lib/hooks/useAiQueue.ts`
**Issue:** AGENTS.md says it is deprecated, but the file is still exported and screens can accidentally import it, creating duplicate `DeviceEventEmitter` subscriptions and duplicate dependency updates on the singleton.
**Fix:** Delete the file. Verify no imports remain.

### 7. Auth errors do not set `serverOnline = false`
**File:** `src/lib/aiQueue.ts:550-553`
**Issue:** The catch block only sets `serverOnline = false` for messages including `'timeout'`, `'Network'`, or `'fetch'`. A 401/403 does not match, so the queue thinks the server is still online.
**Fix:** Add `|| errMsg.includes('401') || errMsg.includes('403')` to the offline detection condition.

### 8. `aiLogger` concurrent-write race condition
**File:** `src/lib/aiLogger.ts:26-57`
**Issue:** `logAi()` does `await getAiLog()` (read) → append → `await setItem()` (write). If two calls happen concurrently (e.g. `enqueue` + `start` for the same job), the second read sees stale data, and the last write loses one entry.
**Fix:** Serialize writes with a simple promise-chain (in-memory write queue) so only one `getItem` → `setItem` sequence runs at a time.

## 🟡 MEDIUM (Edge cases / Inconsistencies)

### 9. `pingServer()` uses `fetch`; rest of AI uses XHR
**File:** `src/lib/aiService.ts:496`
**Issue:** Inconsistent networking stack. Also, `fetch` + `AbortController` has spotty React Native support on older devices.
**Fix:** Rewrite `pingServer()` to use `XMLHttpRequest` for consistency with the streaming path.

### 10. `enqueueBatch()` ignores `MAX_QUEUE_SIZE`
**File:** `src/lib/aiQueue.ts:303-359`
**Issue:** No check against `this.MAX_QUEUE_SIZE` before pushing.
**Fix:** Add a guard: if `this.jobs.length + enqueued > MAX_QUEUE_SIZE`, reject or truncate.

### 11. Orphan recovery preserves stale `error` and `retryCount`
**File:** `src/lib/aiQueue.ts:645-662`
**Issue:** When recovering orphaned jobs, `error` and `retryCount` from a previous crash are kept.
**Fix:** Clear `error` and reset `retryCount` to 0 on orphan recovery.

### 12. `generateTitle` / `generateSummary` accept empty/whitespace text
**File:** `src/lib/aiService.ts:384-433`
**Issue:** No validation on `text` parameter.
**Fix:** Return early with empty result if `!text || !text.trim()`.

### 13. `checkGrammar()` uses `as` type assertions
**File:** `src/lib/aiService.ts:459-464`
**Issue:** Violates `.kilo/instructions/typescript-rules.md` (no `any` / `as` — use type guards).
**Fix:** Extract a `isGrammarSuggestion(item: unknown): item is GrammarSuggestion` type guard.

### 14. Batch job IDs can collide
**File:** `src/lib/aiQueue.ts:273,338`
**Issue:** `Date.now() + Math.random()` in tight loops.
**Fix:** Use `generateId()` from `@/lib/utils`.

### 15. `scheduleNext()` fires even when queue is empty
**File:** `src/lib/aiQueue.ts:585-587`
**Issue:** After the last job, `processNext()` sets `processing = false` and returns. But `scheduleNext()` from the previous iteration fires 500 ms later, running an empty check.
**Fix:** Call `scheduleNext()` only when `getNextJob()` returns a job.

### 16. `processNext()` doesn't validate API key before starting a job
**File:** `src/lib/aiQueue.ts:453-506`
**Issue:** No pre-flight config validation.
**Fix:** After `const config = this.getAiConfig()`, validate `config.baseUrl` and `config.apiKey`. If invalid, fail fast with `nextJob.error = ...` and do not retry.

## 🟢 LOW (Simplification opportunities)

- **Refactor `processNext()`**: It is ~150 lines. Extract helpers: `runJob(job)`, `handleJobSuccess(job, result)`, `handleJobFailure(job, error)`.
- **Simplify comments**: `aiQueue.ts` and `aiService.ts` have extremely verbose JSDoc. Condense to "why" not "what" per AGENTS.md Rule 1.
- **Add `phase: 'batch'` to `AiLogEntry` type**: The type only allows `'title' | 'summary' | 'both'`, but the log calls often pass `'both'`. If batch-level logging is desired later, add `'batch'`.

---

## Implementation Order

1. **Fix Critical 1 & 2 first** — these are user-facing crashes/infinite loops.
2. **Fix Critical 3** — prevents first-time-user silent failures.
3. **Fix High 4-8** — resolves data-loss and race conditions.
4. **Fix Medium 9-16** — stabilizes edge cases.
5. **Delete deprecated `useAiQueue.ts`**.
6. **Update `ai-integration.md`** with any new behavior rules (e.g. API key validation).
7. **Run `aiQueue.test.ts`** and add new tests for:
   - Missing API key guard
   - 401 handling
   - Orphan recovery clears error/retryCount
   - Cancel race condition
